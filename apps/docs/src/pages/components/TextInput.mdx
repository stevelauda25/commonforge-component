## Props

| Prop | Type | Default | Notes |
|------|------|---------|-------|
| `label` | `string` | — | Visible label text above the input. |
| `required` | `boolean` | `false` | Shows a red asterisk next to the label. Also sets the native `required` attribute. |
| `sublabel` | `string` | — | Grey text after the label, e.g. "(Optional)". |
| `labelInfo` | `boolean` | `false` | Renders a small info icon next to the label. |
| `hint` | `string` | — | Help text below the input. Hidden when `error` is set. |
| `error` | `string` | — | Error message — replaces hint, turns border red, sets `aria-invalid`. |
| `leftIcon` | `ReactNode` | — | Icon slot before the input text. |
| `rightIcon` | `ReactNode` | — | Icon slot after the input text. |
| `size` | `'sm' \| 'md'` | `'md'` | Input padding size. `md` = 12px, `sm` = 8px. |
| `type` | `string` | `'text'` | HTML input type (`text`, `email`, `password`, etc.). |
| `disabled` | `boolean` | `false` | Disables the input and dims the container. |

Extends all native `<input>` HTMLAttributes (minus `size` and `type` which are overridden).

## Accessibility

- Native `<input>` under the hood — keyboard, form participation, and screen-reader support come for free.
- `error` sets `aria-invalid="true"` and the error message is linked via `aria-describedby`.
- `hint` is linked via `aria-describedby` when no error is present.
- Focus ring uses `focus-within` on the container so clicking icons also activates the ring.
- `leftIcon` / `rightIcon` are marked `aria-hidden` — they are decorative.

## Things to watch

- This is a controlled-friendly but uncontrolled-compatible component. For controlled mode, pass `value` + `onChange` as usual.
- `error` takes precedence over `hint` — when both are provided, only the error message renders and is linked to `aria-describedby`.
- Icons are decorative (`aria-hidden`). If an icon conveys meaning (e.g. a status indicator), wrap it and add your own `aria-label` on the parent.
