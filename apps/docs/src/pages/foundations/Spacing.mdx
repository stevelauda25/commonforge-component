## Spacing scale

Each step is a discrete value — pick from the ladder, never invent in-between numbers. Tailwind classes shown are what you'll write; pixel values are the resolved size.

## Width scale

Layout containers — page max-widths, content columns, modal frames. Use these as `max-w-[Npx]` in code, or wrap a layout in a fixed shell.

## Common usage

| Class         | Pixels | Use case |
|---------------|--------|----------|
| `gap-1`       | 4      | tight icon ↔ label gap |
| `gap-2`       | 8      | default form-control gap |
| `gap-3`       | 12     | between buttons |
| `gap-4`       | 16     | between sections |
| `p-3`         | 12     | card padding (compact) |
| `p-4`         | 16     | card padding (default) |
| `p-6`         | 24     | page section padding |
| `px-8`        | 32     | wide horizontal padding (desktop container) |
| `space-y-6`   | 24     | between stacked card sections |
| `mt-12`       | 48     | between major page blocks |

## Things to watch

- The named scale (`spacing-xs`, `spacing-md`, etc.) lives in **Figma**, not in the codebase. In code you use Tailwind classes directly — `p-1` not `p-spacing-xs`. The naming map is reference-only.
- Width scale values are not exposed as `max-w-*` Tailwind classes by the preset. Use `max-w-[Npx]` arbitrary syntax for the exact Figma values — the docs site does this throughout.
- There is no `spacing-sm` named token in Figma's variable list, but the 6px step is canonical. It comes from `Spacing/1.5 (6px)` and maps to Tailwind `p-1.5`.
- Don't invent in-between values (`p-[7px]`, `gap-[5px]`). If the design needs a value not on the scale, push back on the design — usually it's a snap to the nearest legal step.
